## 自动执行步骤

1. **识别用户角色** — 从 `user_personas` 提取所有用户角色
2. **梳理功能清单** — 从 BRS 提取所有功能，按角色分组
3. **设计章节结构** — 按"通用 → 角色专属 → 高级 → FAQ"组织
4. **生成操作步骤** — 每个功能包含 5-10 步操作 + 截图位
5. **整理 FAQ** — 基于 `faq_list` + 培训反馈
6. **生成快速上手指南** — 1 页 A4 内的精简版
7. **生成培训课件大纲** — 按角色分章节
8. **输出待确认项** — 列出截图、术语、业务流程待补充项

## 第 3 章 通用功能

### 3.1 业务分析师

#### 3.1.1 自定义查询

**适用场景**：临时数据分析需求

**操作步骤**：
1. 进入"自助分析" → "新建查询"
2. 选择数据源（如 dws_sales_user_d）
3. 拖拽字段到行/列/筛选区
4. 选择聚合方式（求和/计数/平均）
5. 点击"运行"
6. 导出结果（Excel / 图表）

（图：自助分析界面截图）

**示例**：查询"2026 年 6 月北京地区销售额 Top10 品类"

```sql
-- 等价 SQL
SELECT 
    category_name,
    SUM(sales_amt) AS total_amt
FROM dws_sales_user_d
WHERE dt BETWEEN '2026-06-01' AND '2026-06-30'
  AND region_name = '北京'
GROUP BY category_name
ORDER BY total_amt DESC
LIMIT 10;
```

#### 3.1.2 报表订阅

（图：报表订阅配置界面）

**步骤**：
1. 打开任一报表
2. 点击"订阅"
3. 设置订阅频率（每日/每周/每月）
4. 选择接收人（邮箱 / 钉钉）
5. 设置数据时间范围
6. 确认

### 3.2 运营人员

#### 3.2.1 会员分析

（图：会员分析看板）

**5 大模块**：
1. 会员概览（总数、新增、活跃）
2. 会员画像（年龄、性别、地域）
3. 复购分析（30/60/90 天复购率）
4. RFM 分层
5. 营销活动效果

#### 3.2.2 活动效果追踪

**步骤**：
1. 进入"营销分析" → "活动追踪"
2. 选择活动 ID
3. 查看活动期间核心指标变化
4. 对比基线（活动前 7 天均值）
5. 导出活动报告

### 3.3 高管

#### 3.3.1 决策驾驶舱

（图：高管驾驶舱界面）

**核心指标**：
- 销售总额（YoY/MoM）
- 新增用户（YoY/MoM）
- 客单价
- 毛利率
- 库存周转

**特色功能**：
- ⏱ 实时刷新（每 5 分钟）
- 📊 同环比自动计算
- 🔔 异常指标告警

## 第 4 章 高级功能

### 4.1 自定义报表

**适用**：有数据分析基础的用户

**操作步骤**：
1. 进入"自助分析" → "报表设计器"
2. 选择模板或从零开始
3. 配置数据源、字段、聚合方式
4. 添加筛选条件
5. 选择可视化类型（柱状/折线/饼图/表格）
6. 保存并发布

### 4.2 数据导出

**3 种导出方式**：
- 📊 **Excel**：含格式、图表
- 📄 **CSV**：原始数据，便于二次分析
- 🖼 **PNG**：图片，用于汇报

**限制**：
- 单次导出 ≤ 10 万行
- 大数据量请使用"异步导出"（邮件接收）

### 4.3 权限管理

**3 级权限**：
- **查看者**：仅查看分配的报表
- **分析师**：可自助查询
- **管理员**：可管理用户、报表、权限

## 第 5 章 常见问题 FAQ

### Q1: 登录后看不到任何报表？
**A**: 请联系管理员（it@example.com）申请报表权限。

### Q2: 数据加载很慢（> 10s）？
**A**: 
1. 缩小筛选范围（时间/地区）
2. 检查网络（ping bi.example.com）
3. 避开高峰期（9:00-11:00, 14:00-16:00）

### Q3: 数据与源系统不一致？
**A**: 数据 T+1 更新，昨日数据 7:00 后可查。如有疑问请提交工单。

### Q4: 如何申请新报表？
**A**: 填写《报表需求申请单》，提交至 BI 团队（bi-support@example.com），3 个工作日内反馈。

### Q5: 忘记密码？
**A**: 登录页 → "忘记密码" → 通过企业邮箱/手机号重置。

## 日志机制

> 📋 详细规范见 [`LOGGING-CONVENTION.md`](data-pipeline/projects/light-dw-toolkit/LOGGING-CONVENTION.md)

本 skill 执行时遵循统一日志机制 v1.2：

### 日志路径查找

```yaml
1. 读取 project_config.yaml 中的 logging 节:
   - skill_execution_log: 所有 skill 执行的统一入口
   - error_log: 错误日志
2. 若 project_config.yaml 不存在 → 使用默认 ./logs/ 目录
3. 优先级: project_config > 环境变量 DW_PROJECT_CONFIG > 默认
```

### 必须记录的事件

| # | 事件 | 何时 | 字段 |
|---|------|------|------|
| 1 | **START** | skill 启动时 | 时间戳、skill 名、项目名、关键输入参数 |
| 2 | **PROGRESS** | 每完成 10% 进度 | 阶段描述、累计进度 |
| 3 | **END** | skill 主体逻辑完成 | 完成时间、耗时、输出物清单 |
| 4 | **REPORT** | END 之后立即 | 成功/部分/失败、警告数、错误数 |
| 5 | **ERROR** | 任何失败（写入 error.log） | 错误码（E0xx-E9xx）、错误消息、上下文 |

### 任务完成报告

完成后输出：

```markdown
## 任务完成报告 — {skill_name}

| 项目 | 值 |
|------|-----|
| 项目名 | {project.name} |
| Skill | {skill_name} v{version} |
| 启动时间 | {start_time ISO8601} |
| 完成时间 | {end_time ISO8601} |
| 耗时 | {duration_seconds} 秒 |
| 结果 | ✅ 成功 / ⚠️ 部分成功 / ❌ 失败 |
| 警告 | {warning_count} |
| 错误 | {error_count} |
```

### 与其他 skill 的日志协同

- 读取 `project_config.yaml` 的 `logging.skill_execution_log` 作为本 skill 的主日志
- 失败时同时写 `error.log`（与所有 skill 共享）
- ETL 类 skill 还会写 `etl_runtime.log`；质量类写 `quality_check.log`；清洗类写 `cleaning_audit.log`
- 如适用，将执行状态写回 `project_config.yaml` 的 `etl_status.tables`
