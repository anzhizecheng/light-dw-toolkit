# 生成 AI 辅助模式项目主计划 (AI-Augmented Project Plan Generator)

> 💡 **核心思想**：传统项目主计划假设"每个任务都需要人来做"，导致工期长、人力紧、风险高。本 skill 重新定义项目计划 —— **先识别 AI 能做什么，再设计人与 AI 的协作流程**。

---

## 触发词

`项目计划`, `WBS`, `项目主计划`, `甘特图`, `AI 辅助排期`, `AI 节省工时`, `项目排期`, `AI 协作模式`, `智能化排期`

---

## 为什么不用传统模板？

| 传统模板（.mpp / Excel） | 本 skill 输出 |
|--------------------------|---------------|
| 假设每个任务人工完成 | 显式区分 AI 任务 / 人工任务 / 人机协作 |
| 工期固定，无灵活性 | 工期自适应（按 AI 等级 + 团队规模）|
| 关键路径不清晰 | 自动识别"AI 瓶颈"与"人瓶颈" |
| 风险靠经验 | 风险量化（基于 AI 错误率 + 返工率）|
| 输出单一（甘特图）| 多输出（WBS / 甘特 / AI 节省表 / 风险矩阵）|

## 自动执行步骤

1. **加载 SOP 15 阶段基线** — 每个 Phase 的标准工期
2. **应用 AI 能力等级** — 根据 `ai_capability` 调整每个 Phase 的工期
3. **拆分任务为 3 类** — AI 任务 / 人工任务 / 人机协作
4. **识别并行机会** — AI 任务可在后台运行，与人任务并行
5. **计算 AI 节省工时** — 对比传统工期 vs AI 辅助工期
6. **识别关键路径** — 区分"人瓶颈"（需等待人）与"AI 瓶颈"（需等待 AI 排队）
7. **风险评估** — AI 错误率、返工风险、人员变动风险
8. **生成甘特图** — 按"人 / AI 协作"分泳道
9. **输出待确认项** — 列出需 PM 决策的事项

## 关键创新点（与传统的 5 大区别）

### 1. AI 能力图谱

每个 Phase 明确标注 AI 能力等级，避免"AI 万能论"。

### 2. 并行执行

AI 任务可在后台运行，与人任务并行 → 节省日历时间。

### 3. 智能工期

工期 = SOP 标准工期 × AI 调整系数 + 风险 buffer。

### 4. 关键路径双轨

区分"人瓶颈"与"AI 瓶颈"，分别给出风险预警。

### 5. AI 节省量化

不仅说"AI 提速"，而是给出具体人天 / 工时节省数字。

## AI 能力等级自适应算法

```
调整系数 f(ai_capability, phase) = {
    'low':    0.8-0.9,   # 节省 10-20%
    'medium': 0.5-0.7,   # 节省 30-50%
    'high':   0.3-0.5    # 节省 50-70%
}

AI 辅助工期 = SOP 标准工期 × f(ai_capability, phase)
```

### 各 Phase 的 f 系数

| Phase | low | medium | high |

| 1 项目准备 | 0.85 | 0.40 | 0.30 |
| 3 系统需求 | 0.90 | 0.55 | 0.40 |
| 7 数据源分析 | 0.85 | 0.45 | 0.30 |

## Input Validation — 输入不足处理

### 情况 1: 未提供开始日期
**处理**: 使用当前日期 + 默认工期

```
⚠️ 未提供项目开始日期，默认使用 {today}。
是否继续？如需调整请提供开始日期（YYYY-MM-DD）。
```

### 情况 2: 未提供团队规模
**处理**: 使用默认 5 人，按比例调整工期

```
使用默认团队规模 5 人。工期按 5 人估算。
如团队更小（3 人），工期需 +60%；更大（10 人），工期 -40%。
```

### 情况 3: 未指定 AI 能力等级
**处理**: 默认 medium（行业平均水平）

```
使用默认 AI 能力等级：medium（节省 40%）。
如团队 AI 工具熟练度低，建议改用 low。
```

### 情况 4: 未提供里程碑日期
**处理**: 根据 SOP 标准推算 + 输出建议日期

```
⚠️ 未提供客户要求的里程碑日期。
按 SOP 标准推算（基于项目开始日期 + 各 Phase 工期）。
如客户有硬性日期要求，请提供以反推各 Phase 工期。
```

## 关键规范

### 工期估算公式

```
Phase 工期 = SOP 标准工期 × AI 调整系数 + buffer
SOP 标准工期 = base_days × complexity_factor
AI 调整系数 = f(ai_capability, phase_id)
buffer = risk_buffer × people_dependency
```

### 里程碑命名规范

```
M{序号}: {里程碑名称}（{关键交付物}）

示例：
M1: 启动会（启动会纪要）
M5: ETL 上线（DAG 运行）
```

### WBS 编号规范

```
{Phase}.{子任务序号}
{Phase}.{子任务}.{细分}

示例：
1.1 项目章程
8.2 物理 DDL
12.4.1 SQL code review
```
